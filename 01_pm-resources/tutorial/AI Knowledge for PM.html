How AI Actually Works

A flow from your message to a response — and where it all fits in the wider AI landscape
Part 1 — The Flow of a Single Request
STEP 1
User Input
You type a prompt or question in natural language
↓
STEP 2
Tokenization
Your text is chopped into small pieces called tokens — roughly word-chunks. Example: "unhelpful" → "un" + "help" + "ful". This is why AI pricing/limits are measured "per token," not per word
↓
STEP 3
Embedding
Each token is turned into a list of numbers (a "vector") that captures its meaning. Similar meanings → similar numbers, so the model can do math on language instead of just matching exact words
↓
STEP 4
Model / Neural Network
The model reads all the tokens together and figures out which words matter most to each other. Example: in "the bank by the river," it links "bank" to "river," not to "money". This weighing mechanism is called attention
↓
STEP 5
Context Window
Everything the model can "see" at once — your message, chat history, system instructions, any retrieved documents. It has a size limit, like a desk that can only hold so many papers at a time; older content gets pushed off if the chat runs long
↓
If the task needs outside info or actions, the model can branch here:
↓
4a
RAG
"Retrieval-Augmented Generation" — before answering, the model looks things up (a doc, a database, the web) instead of relying only on what it memorized during training
4b
Tool Use
The model calls something outside itself — runs code, checks a calendar, searches the web — like using a calculator instead of doing math in its head
4c
Agent Loop
The model makes a plan, takes an action, checks what happened, then decides the next step — repeating until the task is done
↓
STEP 6
Inference
"Inference" just means the model is being used to produce an answer (as opposed to "training," when it was originally taught). It predicts the next token, over and over, one at a time
↓
STEP 7
Decoding & Temperature
Tokens are turned back into readable text. Temperature is the dial controlling how safe vs. varied the word choices are — low = consistent, predictable answers (good for facts/code); high = more variety and creativity (good for brainstorming)
↓
STEP 8
Response to User
Final answer, image, code, or action result is returned to you
Part 2 — Which Term is a Subset of What
ARTIFICIAL INTELLIGENCE (AI) Umbrella term for any system that mimics human intelligence — includes simple rule-based programs ("if X then Y"), not just modern AI
MACHINE LEARNING (ML) System learns patterns by seeing lots of examples, instead of a human writing rules. Example: shown 10,000 spam emails, it learns what spam "looks like"
NLP — NATURAL LANGUAGE PROCESSING The branch of ML/AI focused on language specifically. Older and broader than LLMs — includes spell-check, translation, sentiment analysis, and 2000s-era chatbots that used simple rules, not neural networks. Example: Google Translate, Grammarly, old-school keyword chatbots
DEEP LEARNING ML using "neural networks" — many stacked layers loosely inspired by the brain. Needs lots of data & compute, but handles messy input like images and speech well
GENERATIVE AI Instead of just labeling or predicting ("is this spam?"), it creates brand-new content — text, images, audio, code
LARGE LANGUAGE MODELS (LLMs)
The modern, deep-learning way of doing NLP — trained on huge amounts of text: Claude · GPT · Gemini · Llama
Computer Vision
Teaching a model to "see" — detect objects, faces, defects in images/video. Example: Face ID, medical scan analysis
Diffusion Models
Generate images/video by starting from random noise and refining it into a picture — Midjourney, Stable Diffusion, Sora
Multimodal Models
One model that handles text + images + audio together, not just one type — Claude, GPT-4o, Gemini
Part 3 — What Turns an LLM into an "Agent"
AI AGENT
An LLM wrapped with tools, memory, and multi-step reasoning — not just one-shot chat
🧠 LLM (the brain)
Core reasoning & generation engine
💾 Memory
Short-term (this chat) + long-term (stored facts/history)
🔧 Tools
APIs, code execution, search, calculators
🗺️ Planning
Breaks a goal into steps, picks the right tool
Agent "types" aren't really separate categories — they're combinations of two things: how many agents are involved, and how much a human is in the loop. RAG is not a separate agent type — it's a tool an agent uses to look things up.
Agent Types — Crossed on Two Axes
Human checks each step (Copilot-style)
Runs many steps on its own (Autonomous)
One agent
(Single-agent)
Assisted single agent
One LLM suggests an edit or action; you approve before it happens
Ex: GitHub Copilot suggesting code you accept line-by-line
Autonomous single agent
One LLM plans and executes a multi-step task with minimal check-ins
Ex: Claude Code writing, testing, and fixing a script end-to-end
Several agents
(Multi-agent)
Assisted multi-agent
Several specialized agents each do a piece, human reviews the combined output
Ex: a "drafter" agent + "editor" agent producing a report you sign off on
Autonomous multi-agent
Several agents coordinate and hand off work to each other with little human input
Ex: a research agent finds data, a second agent analyzes it, a third writes the summary — all automatically
